# Editor

**Scope:** candidate → finished Short. Writer step (Claude Haiku: score, 3 hooks, context line, title) → Whisper word captions → 9:16 → story captions + context line → ≤60 s → mp4.

**HQ decisions (D7, D8, D15, D18):**
- Every clip gets a context line + setup→payoff captions. No raw re-uploads.
- Hard cap 60 s; flag music segments.
- **Market style:** the Writer's cached system prompt includes the Trend Scout format library (`$CLIPPER_FORMATS`, default `/opt/clipper/formats/library.md`; `run_pipeline.refresh_formats()` copies it from the `trends` branch every ≤6 h). Titles and hooks follow what is working that day.
- **Market window:** a Radar pick keeps the length viewers chose (popular Twitch clip / most-replayed YouTube part). The Writer may only trim dead air, max 2 s per end (`market_window()`, `MAX_TRIM_S`). No fixed minimum length.
- No speed-up, pitch shift, mirroring or heavy filters.
- Writer = provider-neutral `llm()` defaulting to Claude Haiku 5.5 (`ANTHROPIC_API_KEY` in `/opt/clipper/.env`); Gemini as fallback.

## Files
| File | What |
|---|---|
| `llm.py` | `llm(prompt, schema) -> dict`. Anthropic `claude-haiku-5-5` by default (`CLAUDE_MODEL` overrides); `LLM_PROVIDER=gemini` uses Gemini (`GEMINI_API_KEY`, `GEMINI_MODEL`). Output is validated against the schema; one retry on invalid JSON. SDK/HTTP imported lazily. **D31:** `llm(prompt, schema, system=None, clip_id=None)` sends `system` as a `cache_control: ephemeral` block (prompt cache); `llm_batch(items, schema, system=None)` runs `[{id, prompt}]` through the Message Batches API (50% cheaper, Anthropic only), polls, returns `{id: dict or None}` (no retry; resubmit the `None` ids). Every call/batch item inserts a row into `llm_usage` (migration 006: input/output/cache-creation/cache-read tokens, `kind` call/batch) when `$CLIPPER_DB` exists; logging never raises. |
| `writer.py` | `write_clip(transcript_window, creator, meta) -> dict`: `score` (0–1), `in`/`out` (≤60 s), 3 `hooks` (≤7 words), `context_line` (≤12 words), `title` (≤70 chars, names the streamer), `music_risk`. Retries once if limits are broken, then raises. |
| `prompts/writer.md` | Writer prompt + score rubric. Everything above the `=== INPUT ===` line is the cached system prompt; per-clip data goes below it only. (hook .30, coherence .25, emotion .20, value .15, payoff .10). Edit here, no code change. |
| `qc.py` | QC v1 (D27): `edited → qc_passed` if the file is ≤60 s (ffprobe), its sha256 is not already in the library (`clips.file_hash`), and fewer than 5 clips passed today (UTC). Otherwise sets `last_error` and leaves the state. `music_risk` passes and stays on the row for the Telegram flag. |
| `rerender.py` | `needs_rerender → qc_passed`: re-cuts the captured source with the new `hook_text` (same start/end + context line; YouTube VOD windows shifted by `capture.section` offset, same as `run_pipeline._picks(file_relative=True)`), replaces the Short in place, refreshes `file_hash`, clears `approval_sent_at`. |
| `clip.py` | Download → Whisper → (`--auto`: Writer on 120 s transcript windows, best N non-overlapping) → render → CSV log. |

## Status
- **Framed like the market (2026-10-21, Lucas: "Did we do the same as him?"):** layout `fit` = the clipper's wide shot: a 1080×900 middle panel that follows the people (~6:5 of the source) over a blurred copy of the video, chat left in its corner. Which layout a clip gets: the matched clipper Short's layout for that moment (thumbnail read by Haiku at match time, `moment_matches.layout`, migration 014) → a matched Short of the same scene (same VOD within 10 min) → the streamer's market layout (style scout, `styles.json` `layout`: full / fit / stack) → our own choice. Market `full` blurs the chat spot instead of adding a chat panel. VM: Ron's fry clip in `fit` passes the visual check; the classifier read his clipper's Short as `fit` and Jynxzi's as `stack`.
- **No black borders, no buried captions (2026-10-21):** rows/columns of the source that stay near-black in 3 frames (by median, so a black bar with a viewer count or a chat line in it still counts) are kept out of every panel (`layout.content_box`; Jynxzi's black stats bar ran across a stack seam as a black band). A stream with its own captions loses that bottom band in every layout, stack included (his sat at the very bottom of the gameplay, under the Shorts UI), and gets ours on the seam/centre. VM: clip 16 re-rendered this way passes the visual check.
- **Stream chat stays readable (`chatstack`, 2026-10-21, Lucas: "U can't even see the chat"):** in crop mode Claude Haiku looks for the stream's chat overlay on two frames (both must agree, box ≤ 35 % of the frame). The picture (following crop) goes on top, the chat box below at full width (newest lines, ≤ 640 px, no bars), its spot in the picture is blurred with a soft edge, and our captions and handle stay above the panel. No chat overlay → plain crop. ~2 small vision calls per IRL clip.
- **Full-bleed crop follows the people (2026-10-21):** faces sampled 2×/s (YuNet); the 9:16 window frames both main faces when they fit, else the biggest, with a deadband (no jitter) and a pan-speed limit (no jump cuts), rendered as one flat ffmpeg `crop` x expression (`layout.follow`, `x_expr`). Before: one static cut on the median face (Stable Ronaldo's fry clip showed a shirt and hands). A stream with its own burned-in captions loses its bottom 14 % in crop mode (`OWN_CAPTION_CUT`, half a caption line otherwise) and gets our captions; stack mode keeps theirs. Each render writes `<clip>.json` (`our_captions`, mode, cut, moving) for the visual check. Captions never run across a sentence end and drop full stops/commas ("TWO. WHAT" → "WHAT HAPPENED?").
- **Same moment as a top clipper's Short (D54):** when Radar matched the clip to a popping clipper Short of the same moment (`radar/match.py`), `clip.same_moment(con, radar_clip_id)` → `draft_pick(same=...)`: the Writer gets `same_moment` {title, dur} and that title first in `popping_now` (so the copy guard covers it); it writes a synonym paraphrase with the same angle and structure, and the target length is that Short's length (clamp 8–60 s).
- **Length follows the top clippers (D51):** `market.target_length(login)` = median length of the streamer's popping English Shorts (market-wide median if < 3, clamp 8–60 s). A Radar window > 1.25× that gets `target_len_s` in the Writer metadata; the Writer picks the best part of about that length (setup + payoff), `writer.check` enforces 0.6–1.4×, and `clip.length_window` falls back to the last `target` s (a stream clip ends on its payoff). Shorter windows keep D37 (trim ≤2 s per end).
- **Per-streamer look (D49, `streamer_style.py` → `styles.json`):** daily, for the 10 streamers with the most Shorts demand, the thumbnails (never the video) of their most popping English Shorts are classified one by one by Claude Haiku (font family, case, colours, keyword colour or none, words, position, header box) and the majority per field is kept (a field with no clear majority keeps yesterday's value, so the look doesn't flip). `style.load(creator=…)` lays it over the global style. Renderer: `condensed` → Anton (OFL, size 124), `geometric` → Montserrat Black; header `white_box` (dark text in a white box, whole clip; on the seam for stack layouts, captions move into the gameplay) or `text` (persistent title) or `none` (2.5 s hook); no keyword colour → plain captions. Style version is per creator, so the bot re-renders a clip when its streamer's look changed. 2026-10-20 VM run: 9 of 10 streamers' popping clips use a condensed font and 7 of 10 plain white captions.
- Visual check: knows this clip's own hook/header text (our white box is not "double captions"), and a failure must be confirmed by a second look. For a streamer we draw no captions for (watchlist `own_captions` or learned), the captions on screen are theirs: `double_captions` is ignored, other problems still count.
- **Titles follow the streamer's popping Shorts (D48):** `clip.market_meta(login)` gives the Writer the streamer's name as fans write it (`caseoh_` → `CaseOh`; the old check forced the login into titles, e.g. "Stableronaldo") and today's most popping English titles about that streamer (`popping_now`, market scan). The Writer copies their style; same moment → a paraphrase with synonyms; `writer.check` rejects a title ≥ 90 % similar to a popping one.
- **Visual check (`visual_qa.py`, D47):** every finished Short (state `qc_passed`) is looked at before it can post: 3 frames (hook at 1 s, ~45 %, ~80 %) → Claude Haiku vision against a fixed checklist (double captions, broken glyphs, blurry panel, bad crop, text overlap, black bars, no watermark) → `clips.visual_qa` (migration 010). Pass → auto-post as before; fail → waits in Telegram with the reason; API error → never blocks. Double captions on a streamer we didn't know captions their stream → learned in `creator_flags`, the clip re-renders without ours and is checked again (once). VM test 2026-10-20 on day-1 Shorts: caught Sykkuno's double captions, found Valkyrae's live captions, flagged the old renders' missing watermark. `VISUAL_QA=0` turns it off. ~3 small images per clip.
- **On-screen text = plain words (Lucas 2026-10-19):** `style.onscreen()` strips emoji/pictographs from the burned-in hook and captions (the font has no emoji, they render as boxes); titles keep theirs. Watermark `@Peakz.Recaps` low-centre (y 1630, ~60 % opaque) like NexxoRecaps; `CLIPPER_WATERMARK` overrides, empty = off.
- Streamers whose stream already shows live captions (watchlist `own_captions: true`, e.g. Sykkuno) get no second caption track; hook + watermark stay (`clip.own_caption_logins`).
- Layout: a corner face under 4.5 % of frame height is a mini cam over an event/IRL broadcast → full-bleed centre crop, not a stack (Adin's 33 px cam was blown up to the top panel).
- `--auto` now uses `writer.py` (no direct Anthropic call). Needs `--creator "Kai Cenat"`; `--meta '<json>'` passes Radar metadata.
- `cap_pick()` enforces ≤60 s on every pick (also `--picks` files) and `render()` cuts with `-t`.
- Context line drawn under the hook (first 8 s); word captions unchanged.
- Radar picks (D23): `python clip.py --picks picks.json --auto` reads `source_url` per pick (uses the captured file when the DB has one), runs the Writer on the transcript inside `start`/`end`, renders. `src` is optional in this mode.
- DB (D24, D22): if `$CLIPPER_DB` (default `/opt/clipper/db/clip.db`) exists and has a `clips` row for the pick, the Writer output (`model_score`, `context_line`, `hooks_json`, `hook_text`, `title`, `music_risk`) is written and the state goes `captured → drafted`; after render `edited` + `file_path`. No DB file → DB writes skipped. A failing pick sets `clips.last_error` and the run continues.
- `clips_log.csv` is now a debug log only; it gains `hook_variant`, `context_line`, `title`, `score`, `music_risk` (old logs are migrated in place).
- Tested on synthetic video only. `--lang es` no longer auto-translates (the old pick prompt did); Spanish captions need `es_words` in a picks file.
- `music_risk` is stored on the row; QC passes it. The Telegram message should show it (publisher change, not done here).
- QC + re-render (D27) are driven by `clipper/run_pipeline.py` (radar → capture → editor → qc → rerender, flock-locked, safe every 20 min). A failed capture/editor/re-render step sets `last_error` and is retried after 2 h.
- Duplicate check = exact file hash. Perceptual hash is not built yet (re-renders with a different hook hash differently).
- Work dirs now live under `$CLIPPER_WORK/<clip_id>/` (default `work/` when unset).

- D31: Writer prompt split into cached system part + per-clip input; `write_clip(..., clip_id=)` tags `llm_usage` rows. Models only cache prompts above a minimum length and the current Writer prompt is short, so `cache_read_tokens` may stay 0 until the rubric/examples grow; `llm_usage` will show it.
- `draft_pick(..., clip_id=)` passes `clips.id` to the Writer, so Radar picks get `llm_usage.clip_id`. Window scoring in `writer_picks` (no `clips` row yet) stays NULL.
- `log_usage` warns (logger `llm`) instead of staying silent if `llm_usage` is missing. **Deploy: run `db/migrate.py` first** (migration 006). It connects with `timeout=30`, like `run_pipeline.py`.
- `llm_batch` is not called by any pipeline step yet (the re-scoring job is a follow-up). Usage rows are `kind='batch'`; the Analyst applies the 50% rate.

## Run

```
python clip.py <url> --picks picks.json                # render chosen picks
python clip.py <url> --auto -n 5 --creator "Kai Cenat" # Writer picks + renders
```
